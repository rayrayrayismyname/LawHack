# PartyRock 建置指南

比賽鼓勵使用低程式平台。這份指南說明如何在 [AWS PartyRock](https://partyrock.aws) 上，用同一套流程做出可以操作的原型。PartyRock 免費、不需要 AWS 帳號，用 Google／Apple／Amazon 帳號登入即可。

> **兩個版本的分工**
> - **PartyRock 版**：比賽規定的低程式原型，評審可以直接點連結操作。
> - **Python 版（本專案）**：展示技術深度。規則引擎是確定性程式，可以測試、不會幻覺；PartyRock 版的「法規檢核」由 AI 依清單判斷，穩定度較低。簡報時可以說明「PartyRock 驗證使用流程，Python 版驗證法律正確性」。

---

## 建置步驟

1. 登入 PartyRock，點 **Build your own app**，App 名稱填「罰單申訴通」。
2. 刪除自動產生的元件，依下表新增 8 個元件（Widget）。
3. AI 元件的模型建議選 Claude 或 Amazon Nova 系列，Temperature 調低（0～0.2），讓結果穩定。
4. 提示詞中的 `@元件名稱` 會引用其他元件的內容，名稱必須完全一致。

| # | 類型 | 名稱 | 說明 |
|---|---|---|---|
| 1 | Document | 罰單檔案 | 上傳罰單掃描檔（PDF）。若不支援照片，可改用手機內建文字辨識，把文字貼到元件 2 |
| 2 | User Input | 罰單內容 | 手動輸入或貼上罰單文字 |
| 3 | User Input | 我的說法 | 白話描述經過與立場 |
| 4 | User Input | 證據說明 | 列出手上有的證據 |
| 5 | AI Text | 罰單欄位整理 | 擷取欄位 |
| 6 | AI Text | 法規檢核 | 依清單逐項判斷 |
| 7 | AI Text | 陳述意見書 | 產生可遞交的文件 |
| 8 | AI Text | 申訴可行性評估 | 附加功能 |
| 9 | Chatbot | 申訴小幫手 | 追問與補充 |

## 元件 5：罰單欄位整理

```
請從下列罰單內容擷取欄位，以條列輸出。看不到的欄位寫「（未提供）」，不要猜測。

罰單檔案：@罰單檔案
罰單內容：@罰單內容

欄位：通知單號、車牌、車種（汽車／機車／大型車）、違規時間、違規地點、違規事實、
違反法條（完整寫出條、項、款）、罰鍰、記點、舉發方式（員警攔停／逕行舉發／民眾檢舉／科技執法）、
舉發單位、應到案處所、應到案日期
```

## 元件 6：法規檢核

這段把 `appeal/rules.py` 的規則改寫成清單。請整段貼上。

```
你是交通違規申訴的法規檢核助手。請依下列「檢核清單」逐項判斷，不得引用清單以外的法條。

【罰單】@罰單欄位整理
【使用者說法】@我的說法
【證據】@證據說明

【檢核清單】
R01（只適用民眾檢舉）民眾僅得檢舉道交條例第7條之1第1項所列項目：
  第30條第1項第2、7款；第30條之1第1項；第31條第6項；第31條之1第1項；
  第33條第1項第2、3、4、6、7、9、11至15款、第4項；第92條第7項；第42條；
  第43條第1項第1、3、4款、第3項；第44條第1項第2款、第2項、第3項；
  第45條第1項第1、3、4、6、10、11、13、16款、第2項；第47條第1項；
  第48條第1、2、4、5、7款；第49條；第53條；第53條之1；第54條；
  第55條第1項第1款（限人行道及行人穿越道臨時停車，機車及騎樓不在此限）；
  第55條第1項第4款（限不依順行方向臨時停車）；
  第56條第1項第1款（限人行道及行人穿越道停車，機車及騎樓不在此限）；
  第56條第1項第10款、第2項；第60條第2項第3款。
  不在清單內、或屬於括號中的例外者 → 明確瑕疵。
R02（只適用民眾檢舉）檢舉日距違規日超過7日 → 明確瑕疵（道交條例第7條之1第2項）。
R03（只適用民眾檢舉）同一輛車違反同一規定，時間相隔未逾6分鐘且未經過路口，只能舉發一次 → 明確瑕疵（第7條之1第3項）。
R04 超速取締，測速點前未設警示標誌，或距離不在一般道路100～300公尺、高速公路及快速公路300～1000公尺內 → 明確瑕疵（第7條之2）。
R05 採證照片車牌、車種與本人車輛不符 → 明確瑕疵（行政程序法第36條）。
R06 採證影像模糊、無法辨識 → 可主張（行政程序法第36條）。
R07 標誌標線遭遮蔽或不清 → 可主張（道交條例第4條、行政罰法第7條）。
R08 為避免緊急危難而不得已 → 可主張（行政罰法第13條）。
R09 違規時非本人駕駛 → 不是撤銷理由，應於應到案日期前辦理歸責他人（道交條例第85條）。

輸出格式：
- 每一項符合的規則一行：［明確瑕疵／可主張／程序］規則編號＋標題：一句話說明＋法條
- 資訊不足以判斷的，列在「待補充」並說明要補什麼
- 都不符合時，明確寫「未發現可主張的理由」
```

## 元件 7：陳述意見書

```
依下列資料撰寫「交通違規陳述意見書」。

【罰單】@罰單欄位整理
【使用者說法】@我的說法
【證據】@證據說明
【檢核結果】@法規檢核

規則：
1. 若檢核結果為「未發現可主張的理由」，不要產生陳述意見書，改為說明建議繳納結案。
2. 「陳述理由」只能使用檢核結果中列出的規則與法條，不得新增其他法條。
3. 「事實經過」只能使用罰單與使用者說法中的事實，不得新增時間、地點或數字。
4. 格式如下：

交通違規陳述意見書
主旨：陳述人不服（舉發單位）（通知單號）號舉發違反道路交通管理事件通知單之舉發事實，依道路交通管理處罰條例第9條第1項規定，於法定期間內陳述意見，懇請撤銷原舉發，不予裁罰。
說明：
一、事實經過：（以「緣陳述人於…」開頭）
二、陳述理由：（一）（二）…
三、檢附證據：附件1、附件2…
四、請求事項：綜上所述，懇請貴機關詳予審酌，撤銷原舉發並不予裁罰。
此致（應到案處所）
陳述人：＿＿＿（簽章）
```

## 元件 8：申訴可行性評估

```
依【檢核結果】@法規檢核 給出申訴可行性等級，只能是「高」「中」「低」其中之一：
- 有任何「明確瑕疵」→ 高，建議申訴
- 只有「可主張」→ 中，可考慮申訴，先補強證據
- 都沒有 → 低，建議繳納結案
- 有「程序」→ 另外提醒在應到案日期前辦理歸責

接著列出：
- 理由（引用檢核結果）
- 成本：罰鍰與記點（取自 @罰單欄位整理）；期限內陳述不需費用；行政訴訟第一審裁判費 300 元由敗訴方負擔
- 參考基準：臺中市108年申訴免罰約20%；臺北市113年科技執法申訴撤銷約10.8%
- 最後一行註明：本評估僅供參考，不代表個案結果，不構成法律意見。
不要輸出百分比形式的勝率。
```

## 元件 9：申訴小幫手（Chatbot）

```
你是罰單申訴小幫手。根據 @罰單欄位整理、@法規檢核、@陳述意見書 回答使用者的追問。
只說明流程與文件內容，不保證結果；涉及檢核清單以外的法律問題，請建議使用者洽處罰機關或法律扶助基金會。
```
