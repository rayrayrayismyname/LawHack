# 部署指南

專案已經整理成可以直接上線的形式：Docker 映像檔、gunicorn 正式伺服器、Caddy 自動 HTTPS、健康檢查、結果自動刪除、AI 呼叫次數限制。下面依情境選一種做法即可。

| 情境 | 建議做法 | 費用參考 |
|---|---|---|
| 比賽 Demo、自己的電腦 | 方案 A：本機執行 | 免費 |
| 有一台雲端主機（VPS／EC2／Lightsail） | 方案 B：Docker Compose＋Caddy | 主機月費 |
| 想用 AWS、搭配 Bedrock | 方案 C：AWS App Runner | 依用量 |
| 想最快拿到網址、不管主機 | 方案 D：Render／Railway 等平台 | 有免費方案 |

---

## 方案 A：本機執行（Mac）

```bash
cd ~/大學/資法黑客松/ticket-appeal-ai
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python web/app.py                  # 開 http://127.0.0.1:5000
```

要讓同一個 Wi-Fi 的手機也能開（例如現場 Demo）：

```bash
HOST=0.0.0.0 python web/app.py     # 手機開 http://<你電腦的區網 IP>:5000
```

### Demo 時開啟 AI（拍照辨識罰單）

1. 安裝 AI 套件：`pip install --timeout 120 -r requirements-ai.txt`
2. 建立設定檔：`cp .env.example .env`，用文字編輯器打開 `.env`，二選一：
   - **Anthropic**：到 console.anthropic.com 建立 API 金鑰並儲值，填入
     `LLM_PROVIDER=anthropic`、`ANTHROPIC_API_KEY=sk-ant-...`
   - **AWS Bedrock**：在 Bedrock 主控台開通模型，用 `aws configure` 設好金鑰，填入
     `LLM_PROVIDER=bedrock`、`AWS_REGION=...`、`BEDROCK_MODEL_ID=...`
3. 檢查連線：`python check_ai.py`，再用罰單照片測：`python check_ai.py 罰單.jpg`
4. 啟動：`python web/app.py`，右上角顯示「AI 已啟用」就完成了。

`.env` 會被自動讀取，而且已列在 `.gitignore`，不會被推上 GitHub。**Demo 前一天先跑一次 `check_ai.py`**；現場網路不穩時，系統會自動退回手動輸入，示範案例仍然可以照常 Demo。

## 方案 B：雲端主機＋Docker Compose（最通用）

適用任何 Linux 主機：AWS EC2、Lightsail、GCP、Azure、Linode、學校主機都可以。

**1. 準備主機**
- Ubuntu 22.04／24.04，1 vCPU、1 GB RAM 就夠。
- 防火牆／安全群組開放 **80** 和 **443**。
- 安裝 Docker：`curl -fsSL https://get.docker.com | sh`

**2. 準備網域（要 HTTPS 就需要）**
- 在網域商新增一筆 **A 紀錄**，指向主機的公開 IP，例如 `ticket.你的網域.com`。
- 沒有網域也能先用 IP 測試，只是沒有 HTTPS。

**3. 上傳專案並設定**
```bash
git clone <你的 repo>  或  scp -r ticket-appeal-ai 使用者@主機:~
cd ticket-appeal-ai
cp .env.example .env
nano .env        # 至少改 DOMAIN；要用 AI 再改 LLM_PROVIDER 等
```

**4. 啟動**
```bash
docker compose up -d --build
docker compose logs -f app       # 看到 "Booting worker" 就是啟動了
curl http://127.0.0.1:8000/healthz
```
打開 `https://你的網域`，Caddy 會在第一次連線時自動申請憑證。

**5. 更新版本**
```bash
git pull
docker compose up -d --build
```

> 主機上已經有 nginx？只啟動 app：`docker compose up -d --build app`，再讓 nginx 轉到 `127.0.0.1:8000`，並保留 `TRUST_PROXY=1`。

## 方案 C：AWS App Runner（搭配 Bedrock）

適合想在簡報中強調「全部在 AWS 上」的情況。

1. **建立 ECR 映像檔庫**，在本機推送映像檔：
   ```bash
   aws ecr create-repository --repository-name ticket-appeal-ai
   aws ecr get-login-password | docker login --username AWS --password-stdin <帳號>.dkr.ecr.<區域>.amazonaws.com
   docker build --platform linux/amd64 -t <帳號>.dkr.ecr.<區域>.amazonaws.com/ticket-appeal-ai:latest .
   docker push <帳號>.dkr.ecr.<區域>.amazonaws.com/ticket-appeal-ai:latest
   ```
   Mac（M 系列晶片）一定要加 `--platform linux/amd64`。
2. **開通 Bedrock 模型**：Bedrock 主控台 →「Model access」→ 開通要用的模型（例如 Amazon Nova Pro）。
3. **建立 IAM 角色**（App Runner instance role），權限至少包含 `bedrock:InvokeModel`。用角色就不需要在環境變數放金鑰。
4. **建立 App Runner 服務**：來源選剛才的 ECR 映像檔，Port 填 `8000`，健康檢查路徑 `/healthz`，環境變數設定：
   `LLM_PROVIDER=bedrock`、`AWS_REGION=<區域>`、`BEDROCK_MODEL_ID=<模型 ID>`、`TRUST_PROXY=1`。
5. 部署完成後會拿到一個 `https://xxxx.awsapprunner.com` 網址，可以再綁自己的網域。

> App Runner 的容器磁碟不保留資料，重新部署後舊結果會消失。這對本專案沒問題，因為結果本來就只保存 24 小時。

## 方案 D：Render／Railway 等平台

1. 把專案推到 GitHub（`.env` 不要推上去，`.gitignore` 已排除）。
2. 在平台建立新服務，選「從 Dockerfile 部署」。
3. 設定環境變數（同下方表格），Port 填 `8000`，健康檢查填 `/healthz`。
4. 平台會給一個 HTTPS 網址。

---

## 環境變數

| 變數 | 預設 | 說明 |
|---|---|---|
| `LLM_PROVIDER` | `none` | `none`（離線示範）、`bedrock`、`anthropic` |
| `AWS_REGION`、`BEDROCK_MODEL_ID` | `us-east-1`、`amazon.nova-pro-v1:0` | Bedrock 設定；模型需支援圖片才能辨識罰單照片 |
| `ANTHROPIC_API_KEY`、`ANTHROPIC_MODEL` | | Anthropic 設定 |
| `DOMAIN` | `localhost` | Caddy 申請 HTTPS 的網域 |
| `OUTPUT_TTL_HOURS` | `24` | 分析結果保存時數，過期自動刪除 |
| `MAX_UPLOAD_MB` | `20` | 上傳大小上限 |
| `AI_RATE_PER_MINUTE` | `20` | 每個 IP 每分鐘最多呼叫 AI 次數，0 為不限制 |
| `TRUST_PROXY` | `0` | 在 Caddy／nginx／雲端負載平衡器後面時設為 `1` |
| `WEB_WORKERS`、`WEB_THREADS` | `2`、`4` | gunicorn 行程與執行緒數 |
| `OUTPUT_DIR` | `/data`（容器內） | 結果檔存放位置 |

## 上線前檢查清單

- [ ] `python -m pytest -q` 全部通過
- [ ] 打開 `/healthz` 回傳 `{"status": "ok"}`，`ai` 欄位是你設定的模式
- [ ] 用 7 個示範案例各跑一次，結果與 README 表格一致
- [ ] 用一張真實罰單照片測試 AI 辨識，逐欄核對
- [ ] 手機開網站，從頭填到下載 Word 檔
- [ ] `.env` 沒有被提交到 Git
- [ ] 若開 AI 模式，到雲端主控台設定費用上限或預算警示

## 隱私與安全設計

- 證據檔案只讀取檔名，**不上傳到伺服器**。
- 罰單照片只在辨識當下送給 AI，**不會存檔**。
- 分析結果與產生的 Word 檔在 `OUTPUT_TTL_HOURS` 後自動刪除。
- 結果網址使用 16 碼隨機代碼，無法被猜到或列舉。
- AI 介面有每 IP 次數限制，避免被濫用造成費用暴增。
- 回應加上 `X-Frame-Options`、`X-Content-Type-Options` 等安全標頭。
